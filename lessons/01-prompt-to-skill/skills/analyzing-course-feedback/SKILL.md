# Analyzing course feedback

Turn a batch of learner feedback into decisions the course owner can act on this week.

## Steps

1. Note the course name, run date, number of responses and the average of each rating column.
2. Group the comments into themes. Tag each theme **Content**, **Trainer** or **Logistics**.
3. Count how many comments support each theme and pick one short, representative quote.
4. Prioritise each fix: **High** if many learners mention it or it blocks learning; **Medium** if it affects experience; **Low** otherwise. Estimate effort as **Quick fix** (before next run) or **Redesign** (needs course change).
5. List what is working, so it is protected in the next revision.
6. Draft a short, constructive note to the trainer.

## Output format

```
<Course> – run <date> – <n> responses
Avg ratings: Overall x.x · Content x.x · Trainer x.x

Improvement backlog
| # | Fix | Type | Mentions | Evidence | Priority | Effort |

Keep doing
- ...

Watch list (1 mention only)
- ...

Note to trainer
<2–3 sentences, strengths first, then one or two asks>
```

## Quality checks

Before replying, confirm:

- Every backlog item is backed by **at least 2 comments**; single mentions go to the Watch list.
- Counts and averages come from the data. Nothing is estimated or invented.
- No learner names or identifying details appear in quotes.
- Trainer feedback is specific and constructive, never personal.
